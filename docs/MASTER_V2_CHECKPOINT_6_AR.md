# هبة الشريف — تسليم الدفعة السادسة

التاريخ: 17 سبتمبر 2026. الأساس: الدفعة الخامسة، commit `0f93ec5`.

هذه دفعة تنفيذ فعلية داخل المصدر القائم. لا تعني إتمام كل مراحل الخطة الأصلية 0–18، ولا نشر التغييرات أو تطبيقها على قاعدة بيانات حقيقية.

## إدارة الموقع والصلاحيات

- الإدارة الرئيسية (المالكة) تحتفظ بجميع الصلاحيات الـ44، بما فيها إدارة الفريق والصلاحيات. لم يُنشأ حساب خارجي ولم تتغير أدوار أي مستخدم حقيقي.
- شاشة إعدادات مركزية تجمع روابط إدارة الصفحات والمحتوى والمنتجات والخدمات والمواعيد والعميلات والمدفوعات والعروض والتقارير والسجلات والأمان.
- محرر الصلاحيات يعرض أسماء عربية واضحة، ويتيح تحديد جميع صلاحيات التشغيل أو اختيارها منفردة. إدارة أدوار الفريق للمالكة، مع بقاء التحقق الأمني الحديث وحماية آخر مالكة.
- قائمة الإدارة تقرأ الصلاحيات الفعلية من قاعدة البيانات؛ منح صلاحية لدور لا يبقى مخفيًا بسبب قائمة ثابتة في الواجهة.
- لا يُسمح بحذف المعاملات أو حقوق العميلات لمجرد توفر الصلاحية. يُتاح حذف السجلات غير المستخدمة، والإيقاف أو الأرشفة مع الاستعادة للسجلات المرتبطة.

## الفتح والإغلاق

أُضيفت خمسة مفاتيح فعلية، تحفظ التغيير والتدقيق معًا:

| المفتاح | الأثر |
| --- | --- |
| الموقع العام | يعرض حالة توقف مؤقت ويمنع إنشاء معاملات جديدة. يستمر الدخول وحساب العميلة وصفحات التواصل والسياسات. |
| الطلبات الجديدة | يمنع إنشاء طلب شراء جديد، بما فيه الطلب المرتبط بحجز مدفوع أو حجز برصيد باقة. |
| الحجوزات الجديدة | يمنع إنشاء حجز جديد أو مهلة حجز جديدة. |
| التواصل | يمنع استقبال رسائل جديدة ويحافظ على الرسائل السابقة. |
| النشرة | يمنع الاشتراك وإعادة الاشتراك، ويُبقي إلغاء الاشتراك متاحًا. |

المنع مطبق داخل قاعدة البيانات، وليس بمجرد إخفاء زر. التحديثات على الطلبات السابقة والتسليم والإلغاء لا تُحظر بهذه المفاتيح. إغلاق الواجهة العامة ليس آلية لإخفاء مواد كانت منشورة أو سحب حقوق سبق شراؤها. يلزم اختبار السيناريوهات المتزامنة على Staging.

## الحزم والمنتجات ومتغيرات الأسعار

- إنشاء وتعديل وحذف الحزم وVIP وأغلفة الموارد المجانية عبر معاملة واحدة تشمل السجل والغلاف وروابطه والمراجعة والتدقيق.
- الحفظ يعيد البرنامج إلى مسودة؛ النشر يبقى إجراءً مستقلًا يخضع لفحص الجاهزية.
- تغيير برنامج منشور أو متغير سعره يتطلب صلاحية النشر أيضًا.
- الغلاف من المكتبة المدارة، مع رفض الصورة المؤرشفة أو الخاصة أو غير المطابقة.
- إغلاق ثغرة استخدام زر حذف البرامج لحذف نوع متخصص مثل كتاب أو دورة.
- تغيير محتويات حزمة منشورة يتطلب صلاحية النشر ويسجل النسخة السابقة.

## الباقات وحقوق المشتركات

- حفظ الباقة وخدماتها ورقم إصدارها وسجلها في معاملة واحدة، دون حذف روابط الخدمات قبل التأكد من نجاح الحفظ كله.
- إتاحة ربط منتج مسودة لمعالجة التعارض السابق الذي كان يشترط نشر المنتج قبل اكتمال باقته.
- الأرشفة، الاستعادة كمسودة موقوفة، وحذف الباقة غير المستخدمة إجراءات مستقلة وواضحة.
- الخدمات والجلسات المسجلة للاشتراك القائم لا تتغير بتغيير الباقة لاحقًا. شاشة العميلة والحجز برصيد الباقة يقرآن العقد المسجل للاشتراك.
- الترحيل يحفظ الخدمات الحالية للاشتراكات القديمة عند تطبيقه؛ لا يدعي استرجاع حقوق تاريخية تغيرت قبل ذلك.
- لا يمكن حذف خدمة مرتبطة بسجل حقوق اشتراك، أو تغيير شروط باقة لها طلب شراء معلّق قبل حسمه.
- أعداد الاشتراكات النشطة تُحسب من المصدر كله، وليست تقديرًا من أحدث 200 سجل معروض.

## العروض والكوبونات

- حفظ، تعديل، تفعيل، إيقاف وحذف مترابط مع المراجعة والتدقيق، والتحقق من الأرقام وحدودها والتواريخ بتوقيت القاهرة.
- بداية ونهاية واضحة، وخصومات تقبل أجزاء الجنيه، وحدود استخدام للكوبون والعرض.
- محرر استهداف متعدد يحفظ كل الشروط بدل فقدانها عند التعديل. يطابق المنتج المحدد أو نوعه؛ التصنيفات القديمة تحفظ كبيانات سابقة ولا تمثل نظام استهداف جديدًا.
- حد العرض يحسب الحجوزات السعرية غير المنتهية والطلبات المدفوعة أو المستردة؛ الإلغاء أو انتهاء الحجز السعري يحرر السعة. قفل سجل العرض يمنع فصل فحص السعة عن حجزها؛ قبول التزامن الفعلي مطلوب على Staging.
- حذف منتج مرتبط باستهداف عرض مرفوض حتى يُعدّل الاستهداف صراحة؛ لا يتحول عرض محدود إلى عرض شامل بسبب الحذف.

## نتائج التحقق وحدودها

- 65 من 65 فحصًا محليًا للعقود والتدقيق نجحت.
- 27 مجموعة اختبار SQL نفذت الترحيلات الفعلية الجديدة على PostgreSQL/WASM محلي مؤقت، بينها فشل تدقيق مقصود بعد الكتابة لإثبات رجوع البيانات والروابط والمراجعات معًا.
- اختبارات SQL تستخدم جداول أساسية مأخوذة من المصدر وعينات مصطنعة للصلاحيات والتاريخ. اختبار أهلية الحجز يعزل إنشاء الحجز اللاحق، واختبار تسعير العرض يعزل جاهزية المنتج. هذا ليس تطبيقًا لكامل سلسلة Supabase ولا اختبار هوية أو RLS أو تزامن حقيقي.
- TypeScript وESLint نجحا، ونجح بناء Next وبناء Cloudflare منفصلين. فحص تبعيات الإنتاج لم يجد ثغرات معروفة وقت التنفيذ.
- لم تُنفذ اختبارات متصفح جديدة. عائق تشغيل وحدات الواجهة الذي سُجل سابقًا لا يزال بوابة قبول مفتوحة؛ لا تُعتبر معاينات سابقة اختبارًا للتعديلات الحالية.
- الترحيلات `087–089` محلية فقط، وتأتي بعد الترحيلات السابقة المعلقة. يجب قبول الاستعادة والتطبيق على Staging قبل الإنتاج. الكود الجديد يعتمد عليها، خاصة قراءة الصلاحيات ومحررات الإدارة.
- لا نشر، ولا تعديل DNS، ولا رسائل خارجية، ولا دفعات أو حسابات أو أسرار خارجية تغيرت.

## الاستكمال التالي

الدفعة السابعة: إكمال مراجعة أدوات التقييمات والإشعارات ورفع الملفات المحمية وإزالتها، وربط العمليات المتبقية بالتدقيق المترابط مع اختبارات الفشل. بعدها تبقى بوابات الاستعادة وStaging وAuth/RLS والتزامن والمتصفح والموبايل والمطابقة البصرية مع مراجع Master V2 الأصلية. لا يُطلب إعادة بناء الموقع من الصفر.

الملف المضغوط يتضمن المصدر الكامل والخطة وسجل القرارات وتقارير التحقق وبصمات الملفات. استُبعدت الأسرار وملفات البيئة ونتائج البناء والحزم وتقارير التشغيل القديمة من أرشيف التسليم.

أُصلحت أداة التغليف لتستبعد فهرس النسخة السابقة من ملفات المصدر قبل إنشاء الفهرس الجديد؛ وفُحصت بصمة كل ملف داخل ZIP مقابل الفهرس الناتج.
