الحالة الحالية: **التجهيز قابل للمراجعة؛ قبول المزود الحقيقي لم يُنفذ؛ الإنتاج محجوز دون تغيير**. الفرع `admin-foundation-phase-one`. لم تُضف ترحيلات بعد 112، ولم يتغير ملف القفل أو تُفعّل خدمة مدفوعة.

## الاتصال المحلي المطلوب فقط

أُنشئ `.env.admin-acceptance.local` من النموذج، ثم تأكد الاحتفاظ به وعدم تتبعه في Git. لا تعرض محتواه. جلسة Supabase CLI الحالية تعمل، لكن قائمة مشروعاتها لا تحتوي مشروع اختبار؛ لم نطلب مفاتيح الإنتاج ولم ننسخها.

القيم الناقصة:

- `NEXT_PUBLIC_SUPABASE_URL` لمشروع الاختبار المنفصل.
- `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` أو البديل القديم `NEXT_PUBLIC_SUPABASE_ANON_KEY`.
- `SUPABASE_SECRET_KEY` أو البديل القديم `SUPABASE_SERVICE_ROLE_KEY`.

يمكن استخدام جلسة CLI الحالية للتهيئة إذا كان الحساب مخولًا للمشروع الاختباري. البديل اتصال قاعدة **الاختبار** في `HEBA_ACCEPTANCE_DATABASE_URL` محليًا. لا حاجة إلى PAT جديد ما دامت الجلسة الحالية مخولة. لا تُرسل أي مفتاح في المحادثة.

يبقى الموقع المحلي `http://127.0.0.1:3170`، والبيئة `staging` والتشغيل `free`. يرفض الحارس مرجع الإنتاج المعروف، والرابط الخارجي للتطبيق، واتصال SQL بمشروع مختلف، ومفاتيح البريد والفحص الخارجي وStream. لا يقرأ المشغّل `.env.local` ولا يستخدمه احتياطيًا.

## أوامر التشغيل على هذا الجهاز

من جذر المستودع، مع جلسة CLI المحفوظة في Windows Credential Manager:

```powershell
# إنشاء الملف إن غاب فقط؛ حفظ القيم الموجودة. بعد وضع رابط الاختبار، قراءة
# مفاتيحه من CLI إن كان ظاهرًا ومخولًا؛ لا اختيار مشروع آخر تلقائيًا.
powershell -NoProfile -File scripts/with-admin-acceptance-cli.ps1 -ScriptPath scripts/setup-admin-acceptance.mjs

# قراءة مستقلة لمراحل الاتصال/تفويض المفاتيح/المخطط؛ لا يكتب بيانات تطبيق.
powershell -NoProfile -File scripts/with-admin-acceptance-cli.ps1 -ScriptPath scripts/check-admin-acceptance-environment.mjs

# خطة المخطط فقط؛ راجعي حالتها والترحيلات قبل التطبيق على الاختبار.
powershell -NoProfile -File scripts/with-admin-acceptance-cli.ps1 -ScriptPath scripts/prepare-admin-acceptance-schema.mjs

# تطبيق الخطة على مشروع الاختبار المحدد فقط.
powershell -NoProfile -File scripts/with-admin-acceptance-cli.ps1 -ScriptPath scripts/prepare-admin-acceptance-schema.mjs -ScriptArguments '--apply'

# التشغيل الحقيقي: حسابات مصطنعة، بناء مستقل، Auth والتطبيق وPostgREST وStorage.
powershell -NoProfile -File scripts/with-admin-acceptance-cli.ps1 -ScriptPath scripts/run-admin-acceptance.mjs
```

لا ينشئ أي أمر مشروعًا أو اشتراكًا. لا `db reset` أو `db push`. المشغّل الافتراضي لا يطبق مخططًا ناقصًا تلقائيًا؛ `--prepare` خيار صريح يجمع التهيئة والتشغيل على الاختبار. لا تستخدم غلاف `.launch-tools` القديم الذي يحمل إعدادات الإنتاج.

## المراحل ومعنى نتائجها

| المرحلة | ما تثبته | الخطوة التالية |
|---|---|---|
| configuration | توفر القيم وحواجز عزل المشروع | إكمال أسماء القيم الناقصة فقط |
| auth_connection_public_key | استجابة Auth بالمفتاح العام | فحص مفتاح الخادم مستقلًا |
| server_key_authorization | طلب إداري حقيقي إلى Auth، دون طباعة الحسابات | فحص PostgREST وStorage |
| postgrest_connection | بوابة REST تستجيب، حتى لو غابت pages | فحص المخطط |
| storage_connection | طلب مخازن حقيقي؛ القائمة الفارغة نجاح اتصال | إنشاء مخازن التطبيق ضمن الترحيلات |
| schema: empty | مشروع متصل بلا مخطط التطبيق | خطة 000–112؛ ليس فشل اتصال |
| schema: partial | مخطط/سجل ناقص | مقارنة المصدر والتعريفات ثم الترحيلات المفقودة |
| ready_for_runtime_checks | وجود علامات المخطط والسجل المطلوب | مقارنة أجسام الدوال ثم تشغيل القبول؛ ليس نجاحه |
| integrated_acceptance | `NOT_RUN` في فحص البيئة دائمًا | المشغّل الحقيقي وتقرير كل حالة |

النتيجة `passed` تخص الحالة المسجلة فقط. `failed / behavioral_failure` فشل سلوكي؛ `environment_blocked` تعذر شبكة/مهلة/حصة؛ `not_run` لم تُنفذ بسبب مرحلة سابقة. لا يتحول التعذر أو فحص البيئة إلى نجاح. خروج 2 يعني أن العمل يحتاج متابعة. تبقى `browserAcceptance` و`workerParity` غير منفذتين في مشغّل HTTP حتى استكمال فحص المتصفح وبيئة Worker.

## تهيئة المخطط واستئنافه

يقرأ المشغّل الجداول وعدد مستخدمي Auth وملفات Storage وسجل الترحيلات. يرفض تبني مشروع غير مملوك للأداة يحتوي حسابات أو ملفات، ويرفض المخطط غير المسجل أو الدوال/سياسات Storage المجهولة في مشروع يفترض أنه فارغ. لا يستنتج التطابق من أسماء الجداول.

في مشروع فارغ: يطبق المصدر 000–112 بالترتيب. في مشروع جزئي: يقبل بادئة متصلة من سجل يطابق النص المحلي، ويطبق المفقود فقط. الاختلاف أو الفجوة أو إصدار مجهول يوقف العمل للمراجعة. يفحص أجسام 13 دالة حرجة عند اكتمال المصدر، ومنها تعريف 096 الصحيح بعد 056، ودوال الاستعادة والرفع والقوائم. هذه مقارنة حرجة محددة، وليست إثبات تطابق كل كائن بالقاعدة.

ينشئ `heba_acceptance_control` غير المكشوف لأدوار التطبيق، بعلامة المشروع وسجل التشغيل والبصمات. كل ترحيل وسجله وبصمته في معاملة واحدة؛ تُزال أغلفة المعاملة الخارجية من ستة ملفات تاريخية عند التنفيذ فقط، ويظل نص المصدر الأصلي محفوظًا في السجل. عند فشل ترحيل يُلغى ذلك الترحيل، ثم تعاد قراءة الحالة قبل الاستئناف. لا تُنسخ جداول الإنتاج أو مستخدماته أو المالكة أو ملفات Storage التابعة له.

## ما يجهزه المشغّل الحقيقي

- 12 حساب Auth مصطنعًا ببريد `example.invalid`: عشرة أدوار إدارية، ومستحقة وعميلة غير مستحقة. إنشاء الحسابات وتعيين أدوار fixtures إعداد اختبار معلوم؛ **لا إدخال صفوف admin_sessions ولا حقن صلاحية الطلب**.
- كلمات المرور عشوائية في الذاكرة فقط، دون ملف أو argv أو سجل. دخول المالكة الاصطناعية عبر `ownerPasswordLogin` في التطبيق؛ بقية الأدوار الإدارية عبر `adminPasswordLogin` ثم عاملين TOTP حقيقيين في GoTrue وإجراء إنشاء جلسة التطبيق. العميلتان تستخدمان SDK المصادقة الفعلي دون صلاحية إدارية. لا يُستخدم حساب المالكة الحقيقي.
- نسخة بناء مستقلة تستبعد كل `.env*` والمجلدات الخاصة، بالاعتماد على القفل نفسه. التطبيق على loopback فقط مع بوابة staging. يرفض منفذًا مستخدمًا، ولا يوقف عملية أخرى.

مرآة البناء تنسخ `src/public/patches` وملفات البناء المحددة فقط، لا التقارير أو صادرات SQL المحلية. تُبنى في مجلد مؤقت مستقل خارج المجلدات المستثناة من Git، بgraph اعتمادية خاصة وقفل مجمد يشمل اعتماديات البناء. يُستفاد من مخزن pnpm المحلي دون نسخ إعدادات npm الحساسة أو ربط node_modules خارج حدود Turbopack. لا تحديث عشوائي. تبقى `.next` وإعدادات المزود خاصة بمرآة الاختبار. يرفض الفحص وضع مفتاح خادم في خانة المفتاح العام قبل أن يصل إلى البناء.

يُفحص المنفذ قبل البناء وقبل بدء الخادم، ثم تُثبت هوية بوابة staging برفض الطلب بلا بياناتها وقبول بياناتها العشوائية الخاصة بالتشغيل. لا يكفي وجود خادم آخر يرد 200 على المنفذ لبدء إرسال كلمات مرور fixtures إليه.
- الحفظ وإعادة القراءة من PostgREST، والاستعادة القديمة/المتزامنة. فشل تدقيق داخل قاعدة الاختبار عبر trigger محدد للصف المصطنع لإثبات إلغاء التحديث ونقطة الرجوع معًا؛ يحذفه `finally` والتنظيف القابل للاستئناف.
- تهيئة Home كمسودة، ومقارنة المصدر، وتحريرها دون ظهور التعديل في العامة. معاينة خاصة فعلية: grant صالح، رفض غيابه وطلب غير المخولة، ثم انتهاء موعد ذلك grant فقط في قاعدة الاختبار. الرابط صالح لحامله وفق تصميم التطبيق؛ لا يُفترض أنه يتطلب تسجيل دخول الزائرة.
- أسماء الاختيارات المؤرشفة والمخفية ومعرّفاتها، و53 صفحة مصطنعة للقوائم والصفحة الأخيرة والبحث الحرفي، ومصفوفة الصلاحيات عبر PostgREST.
- ملفات أصلية مصطنعة PDF وPNG وMOV، دون نسخ ملفات إنتاج. حدود المخازن الخمسة: أقل ببايت، مساوٍ، أكبر ببايت، عبر توقيع/رفع حقيقيين وتسجيل وسائط فعلي، مع رفض Storage للتجاوز. MOV ذو إطار RGB أصلي؛ هذا اختبار نقل وتسجيل، وليس قبول ترميز تشغيل الفيديو في المتصفح.
- ربط كتاب ومورد درس عبر تصريح الرفع الفعلي، إعادة إنهاء نفس التصريح دون ازدواج، وفشل التحقق قبل وصول الملف ثم إعادة المحاولة نفسها. تنزيل الكتاب للمستحقة ومقارنة SHA-256، ورفض غير المستحقة والرابط العام للملفات الخاصة، ثم خروج الإدارة وإلغاء جلستها.

منح استحقاق كتاب صفري الثمن هنا fixture مصطنع لاختبار الوصول؛ لا يحاكي اعتماد دفع أو يحدد سياسة مالية. اختبارات HTTP لا تثبت إرسال نموذج المتصفح أو سلوكه مع Secure cookies أو Enter. تبقى تلك خطوات قبول فعلية منفصلة بعد الاتصال، مع مقارنة البيانات قبل البحث وبعده، وتجديد الصفحة، ولقطات الواجهات الحقيقية.

## التنظيف والتراجع

التقارير المحلية في `.launch-tools/admin-acceptance/reports/`، بلا كلمات مرور أو مفاتيح أو روابط المعاينة/التنزيل الموقعة. سجل fixtures يحفظ المعرفات ومسارات الملفات فقط. التنفيذ يتوقف عند أول فشل، ويُسجل الباقي غير منفذ، ثم يوقف عمليته المحلية وينظف.

التنظيف يتحقق من علامة المشروع وسجل التشغيل المخزن، ومن عنوان الحساب المصطنع ووسم التشغيل. يستعيد الحساب الذي أنشئ قبل انقطاع حفظ manifest عبر **العنوان المتوقع والوسم معًا**، ويستعيد مسارات التصاريح ووسائط الحسابات المحددة. يحذف فقط الملفات المسجلة، ثم أحفاد مفاتيحها الخارجية وصفوف الجذور المحددة، ثم تلك الحسابات. لا truncate ولا حذف بالشبه العام. يؤكد غياب ملفات Storage والحسابات قبل إغلاق السجل. أي علاقة لم تُحل أو فشل تنظيف يبقي التشغيل مفتوحًا ويمنع بدء تشغيل جديد.

بعد توقف قسري أو تعذر التنظيف، استخدمي **fixtureRun / cleanupRun** من التقرير:

```powershell
powershell -NoProfile -File scripts/with-admin-acceptance-cli.ps1 -ScriptPath scripts/run-admin-acceptance.mjs -ScriptArguments '--cleanup=معرف-التشغيل-المصطنع'
```

لا تُرجع المخطط بإسقاط الجداول. ترحيل الاختبار الفاشل يُلغى بمعاملته؛ الناجح يبقى للاستئناف. الرجوع عن تحسينات الواجهة يكون بعكس commits الواجهة فقط، دون حذف بيانات أو تصاريح عميلات. لم يُطبق شيء من 108–112 على الإنتاج في هذا التسليم. خطوات الإنتاج والنسخ الاحتياطي والتراجع الواردة في `ADMIN_FOUNDATION_PHASE_ONE_AR.md` تظل محجوزة حتى قبول المزود والمتصفح ومراجعة النتائج.
